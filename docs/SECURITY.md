# 보안 설계와 범위

## 사이트 회원 인증

회원 비밀번호는 PBKDF2-SHA256, 개별 salt, 100,000회 반복으로 해시합니다. 평문 회원 비밀번호를 저장하지 않습니다. 인증 토큰도 서버에는 SHA-256 해시로 보관합니다.

쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`, `__Host-` 접두사를 사용합니다. 자동로그인을 선택하면 최대 30일, 선택하지 않으면 브라우저 세션 쿠키와 서버 측 최대 24시간 만료를 사용합니다. 브라우저의 세션 복원 기능은 세션 쿠키를 복원할 수 있습니다. 비회원 조회 세션은 주문 범위로 제한됩니다.

이메일·IP별 요청 제한과 변경 요청의 Origin·JSON Content-Type 검사를 적용합니다. 관리자 권한은 신뢰할 수 있는 플랫폼 인증과 등록된 운영자 목록으로 확인하며 자체 가입만으로 관리자 권한을 얻을 수 없습니다.

## 게임 접속정보 전달

게임 아이디·비밀번호·2차 비밀번호는 회원 가입용 비밀번호와 별개입니다.

1. 신청 페이지는 입력값을 페이지 메모리에 잠시 유지합니다. 최초 대기 데이터는 5분 후 지우며 브라우저 영구 저장소를 사용하지 않습니다.
2. 주문 API에는 게임 로그인 정보를 넣지 않습니다. 관련 필드가 들어온 요청은 거부합니다. OTP는 사용 여부만 저장하고 OTP 코드를 수집하지 않습니다.
3. 고객과 승인된 담당자 사이에서 SDP offer/answer로 WebRTC 연결을 협상합니다. 서버는 게임 로그인 정보 대신 연결 메타데이터만 일시 저장합니다.
4. 고객이 연결된 담당자를 확인하고 전송을 누르면 암호화된 RTCDataChannel로 일회성 전송합니다. 전송 직전 현재 연결·수신자를 재검증합니다.
5. 수신 확인 후 고객 입력값을 비우고 연결 메타데이터를 정리합니다. 담당자 화면은 기본 마스킹하고 60초 뒤 지우며, 닫기·명시적 삭제로도 제거합니다.

담당자 재배정, 권한 철회, 만료 또는 종료된 주문에서는 연결을 제한합니다. 한 연결에 수신 담당자 한 명만 참여하도록 검사합니다.

## 한계

페이지 메모리 삭제는 JavaScript 참조와 입력값을 비우는 방식이며 메모리를 물리적으로 덮어쓰는 보장은 아닙니다. 수신자가 열람한 정보의 수동 복사·촬영까지 막을 수는 없습니다.

직접 연결에는 공용 STUN 서버를 사용합니다. 네트워크 주소 정보가 연결 상대 및 STUN 서비스에 노출될 수 있습니다. 게임 비밀번호는 STUN·시그널링 서버로 전송하지 않습니다. TURN 중계가 없어 일부 NAT·방화벽에서 연결할 수 없습니다.

이메일 인증, 비밀번호 재설정, 계정 MFA는 아직 구현하지 않았습니다. 보안 검증 테스트 통과는 외부 보안 감사나 모든 네트워크에서의 연결 보장을 의미하지 않습니다.

## 저장소 관리

`.env`, 인증 토큰, 실제 호스팅 식별 설정, 운영 DB, 로컬 주문·회원 정보는 커밋하지 않습니다. 로그에 게임 로그인 정보를 추가하지 마세요. 취약점 보고에 비밀번호나 실제 고객 데이터를 포함하지 않습니다.
