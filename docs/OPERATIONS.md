# 운영 안내

## 새 환경 준비

1. Node.js 22 이상과 Python 3을 설치합니다.
2. `.openai/hosting.example.json`을 `.openai/hosting.json`으로 복사합니다. 실제 Sites 프로젝트를 등록할 때 발급된 프로젝트 ID를 이 로컬 설정에 넣습니다. 기존 운영 사이트의 ID는 이 저장소에 포함하지 않았습니다.
3. D1 데이터베이스를 연결하고 바인딩 이름을 `DB`로 설정합니다.
4. `drizzle/0000_live_orders.sql`부터 `0003_secure_connections.sql`까지 순서대로 한 번씩 적용합니다. Sites의 마이그레이션 저널은 `drizzle/meta/_journal.json`에 있습니다.
5. 런타임 변수 `OWNER_EMAIL`을 소유자 계정 이메일로 설정합니다. 이 값은 소스에 하드코딩하지 않습니다.
6. Sites 운영자 인증과 외부 접근 정책을 확인합니다. 로컬 미리보기의 헤더 주입 기능은 배포 경로에 포함하지 않습니다.
7. 빌드 후 해당 환경의 배포 절차로 게시합니다.

## 접수 시작 전 설정

운영 설정에서 대표자, 고객센터, 운영시간, 입금 은행·계좌·예금주, 확정 요금, 이용 안내·개인정보 처리방침·취소환불 기준을 입력합니다. `pricingConfirmed`와 `acceptingOrders`를 활성화하고, 추가 담당자는 운영 설정의 운영자 목록으로 관리합니다.

운영 설정은 DB에 저장되며 GitHub 소스에는 실제 설정값을 복사하지 않습니다.

## 일상 처리

고객이 신청하고 계좌이체 → 고객이 입금 사실 알림 → 운영자가 실제 은행 입금 확인 → 담당자 배정 → 양쪽 브라우저에서 보안 전달 연결 → 고객이 접속정보 일회성 전송 → 작업 진행 및 완료 처리.

고객의 입금 알림만으로 입금 확인 상태가 되지 않습니다. 취소환불 상태를 변경해도 실제 은행 환불이 자동 실행되지는 않습니다.

## 백업 및 계정 관리

회원·주문·입금 관련 데이터는 운영 DB에서 관리합니다. 소스 저장소는 운영 DB 백업이 아닙니다. 운영 DB의 접근 권한과 백업·보존 정책을 별도로 관리하세요. 운영자 추가·삭제 및 담당자 재배정 후에는 접근 권한과 보안 연결을 확인합니다.

## 로컬 실행 파일

- `scripts/build.mjs`: 현재 소스에서 Worker 번들 생성
- `scripts/preview.mjs`: 루프백 로컬 서버 및 SQLite DB
- `scripts/readable-fixture.mjs`: 로컬 디자인용 예시 운영 설정
- `scripts/test-all.mjs`: 현재 회귀 테스트 세 묶음 실행

기타 `integrate`, `prepare`, `add`, `restyle` 등의 스크립트는 초기 제작 이력입니다. 새 배포나 로컬 실행을 위해 일괄 실행하지 않습니다.
